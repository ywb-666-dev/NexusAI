# 我的信息电台

入口 `/radio`，或在已完成且有事件的个人简报点击“收听这份简报”。节目复用用户自己的简报，覆盖其实际订阅的话题，不限定职业或领域。最近 50 份简报中的有内容节目可选择，旧简报可通过简报页面的链接进入；没有节目时引导先完成订阅、采集与简报。

## 收听和卡片

播放内容包括开场概览、事件标题、事实摘要及标明为建议的关注事项。使用浏览器和设备提供的 SpeechSynthesis 声音，不需要额外语音服务密钥，不生成服务器音频文件。声音及兼容性参考 [Web Speech API 文档](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis)。

- 用户点击才播放，支持暂停/继续、停止、上一条/下一条、点击事件跳转、0.8/1/1.2/1.5 倍速和设备声音选择。
- 朗读文本按标点和最多 140 个 Unicode 字符分段；当前事件和播报片段同步显示，播放结束自动进入下一事件。停止或切换节目会取消旧队列，旧回调不能跳动新节目。
- 聚焦追问或发送快捷问题会暂停朗读；回答完成后由用户继续。切换到后台也自动暂停，离开页面取消声音。
- 按当前账号在浏览器本地保存简报 ID、事件与分段位置；不保存正文或令牌到播放进度中。只对当前账号可访问的节目恢复，不自动播放。清除浏览器数据会清除位置，暂无跨设备进度同步。
- 声音由设备决定，部分设备需要安装中文语音包。无声音时明确禁用播放并提示，阅读和追问仍可使用。设备声音可能使用设备厂商的联网服务；这不是“保证完全离线”的承诺。
- 时长依据字数与速度估算，进度条是事件位置，不是精准音频时间轴。没有音频下载、真人声音克隆、实时语音输入、锁屏续播或模拟双主持人。当前同步卡片以文字与来源为主，不抓取未经确认的配图。

## 围绕当前事件追问

快捷问题包括讲简单一点、为什么值得关注、有没有不同说法，也可输入最多 500 字的自定义问题。通过已配置模型处理，最多同用户一个进行中请求、3 秒提交间隔，复用全局模型并发限制；模型请求外层 90 秒，前端等待 110 秒。没有额外每日用量配额，每次实际追问可能消耗模型额度。

只提供当前事件引用的最多 6 篇资料及最近 4 轮对话，原文来自简报保存的片段；不实时搜索，不把历史模型回答当成事实来源。要求区分事实、解释、建议和未知信息；票价、时间、健康或金融等问题缺少证据时明确说资料不足。

模型返回严格结构：回答、是否资料不足、局限、来源 ID 和逐字引文。非不足回答必须有依据；未知/重复 ID、空白引文、编造引文、错误类型均不保存。依据只能来自当前事件的原文标题、摘要或正文，不能引用其他事件的资料。引用校验不能独立证明结论真实或完全消除模型误判。

成功回答保存到 `radio_turn`，当前事件最多显示最近 20 轮，重新进入仍可阅读。失败明确返回 503，不伪造答案；网络断开时服务端可能已保存，重试前可刷新事件历史。MySQL 5.7 下提交后显式刷新服务器生成时间，避免异步隐式加载错误。

## 偏好和追踪

“这类消息少一点”将当前提供的资料对应、仍归用户所有且已发布的文章标记不感兴趣，复用推荐算法的负反馈，影响后续推荐及新简报；支持撤销。当前节目与历史简报保留快照，不删除原文，不代表全站永久屏蔽同一主题。

“追踪后续”经确认后复用原订阅的来源，生成自然语言语义订阅，**默认暂停**。用户需在“我的订阅”检查条件和来源后启用；没有可复用来源时明确提示。重复点击同一事件复用已有追踪订阅；删除后允许重新创建。没有因追踪按钮立即启动采集、模型处理或推送。启用后的采集、审核、通知沿用已有流程，不承诺严格识别所有新进展。

新增 `radio_follow` 复合键确保每用户/简报/事件幂等。所有简报、对话、偏好和追踪接口按用户鉴权，不允许通过管理员身份读取其他人的私人节目。

## 接口和验收

- `GET /api/python/radio/{brief_id}/events/{index}`：事件资料、最近对话、偏好和追踪状态。
- `POST .../ask`：`{"question":"这件事讲简单一点"}`。
- `PUT .../preference`：`{"dismissed":true}`，严格布尔值。
- `POST .../follow`：幂等创建暂停的语义追踪订阅。

启动时非破坏创建 `radio_turn`、`radio_follow`。运行全部后端回归，或 `python scripts/radio_check.py --real-model` 执行隔离普通账号的完整验收。后者调用当前真实模型处理两条明确合成的生活文化资料问题，不做真实采集或机器人发送；故意坏输出测试使用进程内替身，不改写真实配置。

结果 `.runtime/radio-result.json` 区分实际可用设备声音数与播放控制替身。无语音包的无头浏览器使用明确标注的语音对象替身验证暂停、切换和卡片交互，不能把替身算作真实音频听感证明。桌面和手机截图同目录。完成验收后执行 `python scripts/dev.py stop --infra`。
