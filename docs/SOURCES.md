# 数据源目录与维护

目录文件：`nexus-python/app/data/sources.json`。当前包含 **348 个不同 URL 的来源，来自 233 个域名，74 个为中文来源**。其中 305 个 RSS/Atom 频道、43 个 API/JSON Feed；后者包含 40 个 GitHub Releases 和 3 个 JSON Feed。数量包含同一网站的栏目、arXiv 学科和同平台的不同项目，不代表 348 家独立媒体。

分类包含人工智能、科技数码、编程与开源、网络安全、科学与学术、新闻资讯、商业财经、设计与产品、生活与文化。中文来源包括少数派、IT之家、Solidot、阮一峰、美团技术团队、博客园等；英文来源包括 GitHub Blog、OpenAI、Google、技术项目官方博客、学术和媒体频道。

本轮补充开源工具与模型的项目发布、开发者博客、央行和国际机构公开信息、科学与文化频道，以及播客节目简介。播客仅采集公开文字简介和原文链接，不下载或转录音频。来源条目类型仍使用 rss/api，以兼容现有订阅、任务和正文处理流程。

## 使用

### 无需了解 RSS 的订阅方式

新建订阅默认使用语义订阅和“系统自动匹配”。填写自然语言“订阅需求”即可；切换兼容模式后才使用“关注主题”（例如人工智能、Python、网络安全）。订阅名称首次自动填入，无需填写来源地址。系统从已维护的目录中按主题相关性、最近可用状态、抽取质量、历史成功率和语言偏好排序，最多加入 5 个不同域名的来源。宽泛的 AI 等主题会遵守中文优先设置，具体项目或站点名称优先精确匹配。

系统来源展示名称、选择理由和“系统来源”标记。用户可排除单个来源、恢复排除列表，或切换到手动配置；“额外来源”保留用户填写的地址与名称。同一 URL 同时属于两者时，以用户来源为准并去重。每个订阅总计最多 20 个来源，系统只使用剩余位置。

开启自动匹配的订阅在保存/启用和采集任务创建时重新计算系统来源。暂停已有订阅时保留现有来源并应用排除列表，不依赖采集服务响应；启用后重新匹配。定时与手动任务使用同一入口，额外来源不会被刷新过程删掉。未开启自动匹配的旧订阅保持手动模式，可编辑后主动开启。

健康检查失败或超过 48 小时未检测的来源不自动加入；有效空订阅允许选择并注明暂无条目。全新数据库尚未检测时，界面/保存可按需检查最多 4 个不同域名的相关候选；自动试采和任务刷新不会为此写入健康检查。没有可靠匹配且没有额外来源时，保存会返回提示，不会加入无关地址。可调整主题、等待巡检或手动配置；已填写额外来源时仍可保留并采集它们。

兼容模式按主题检索来源目录；语义模式会先调用模型理解自然语言需求，再据此选取候选来源，文章还需独立语义审核。自动匹配仍限于已维护目录；用户可通过“从网站发现来源”补充公开订阅地址，不是任意网站全网搜索。详见 [语义订阅说明](SEMANTIC.md)。自动匹配和后台健康检测都保留来源真实的 rss/api 类型，不把 API 地址误当作 RSS。

策略保存在 `trigger_conditions.source_policy`（`mode`、`topic`、`language`、`excluded_ids`），无需新增数据库列。`rss_feeds` 保存生效地址及 `origin`（manual/system）、`sourceId`、`reason`。Java 写入入口与 Python 调度入口都会执行规则，直接调用 API 也可使用自动来源，不依赖前端填地址。排除列表最多 50 个来源 ID。

### 直接浏览来源目录

1. 进入工作台的“数据源中心”，按名称、主题、域名、分类、语言、状态或 RSS/API 类型筛选。
2. 点击“预览与检测”查看真实标题、摘要、最近检测时间及错误；检测按来源类型读取，不触发文章发布或推送。
3. 跨页最多选择 20 个来源，加入一个新订阅，或合并到现有订阅。合并时按 URL 去重，并保留已有订阅的关键词、暂停状态、AI 开关和采集间隔。
4. 新订阅默认语义筛选，每 60 分钟采集，额外翻译关闭；语义筛选仍需要模型。来源较多时应按主题拆成多个订阅。
5. “导出 OPML”仅导出当前筛选内的 RSS/Atom；API/JSON Feed 不伪装为 RSS。响应头 `X-Nexus-Skipped-Sources` 标明跳过数量。“导出 JSON”保留所有筛选内来源的真实类型，不包含健康样本。JSON 目前为目录备份格式，不提供批量导入。

### 从网站或项目发现来源

输入公开网站、RSS/Atom/JSON Feed 地址，或 `https://github.com/owner/repo` 仓库地址。网站发现只读取页面公开声明的前 6 个 `link rel="alternate"`（RSS、Atom、JSON Feed MIME 类型），支持相对路径与 HTML base；最多 3 个地址同时验证。直接输入 feed 时复用已读取响应，不重复抓取。GitHub 仓库转换为官方公开 Releases API，不下载源码或二进制。

发现只读，不创建订阅、采集任务、文章、通知或公共目录条目。验证可读或有效空源后，用户再选择“使用此来源创建或加入订阅”。合并已有订阅会保留暂停状态与其他条件；失败地址禁止加入，并显示超时、访问受限、请求配额等原因。

接口为 `POST /api/python/sources/discover`，请求 `{"url":"https://example.com"}`，要求登录；同用户最多一个进行中请求、10 秒间隔，全局并发为 2，总时限 40 秒；初始网站读取 12 秒、单 feed 验证 10 秒。最多验证 6 个地址，不扫描猜测路径，也不绕过登录、验证码或付费墙。所有地址和跳转使用现有公网地址检查、4 MB 限制和有界网络重试。

JSON Feed 支持 1/1.1 的正文、摘要、作者和日期，仍需可打开的文章地址；不支持只有 ID 或附件的条目。GitHub 保留官方发布页 html_url 和发布说明，跳过草稿，不包含没有关联 Release 的普通 Git 标签；没有 Release 的仓库返回有效空列表。公开 API 有匿名请求配额，耗尽时如实标为失败，不关闭校验或自动切换第三方代理。

## 可用性含义

2026-10-26 原有 217 条目录检查为 **119 个可返回文章、45 个有效空订阅、53 个失败**。扩展阶段另检查了 156 个新候选：106 个返回文章、1 个有效空列表、49 个失败；其中 25 个格式/地址不适配或重复候选已剔除。最终保留的 131 个新增来源对应 **106 可用、1 空、24 失败**。这两批是不同时间的观测，不叠加成当前可用数量；界面以数据库最近检测为准。

- **可用**：该次请求成功，返回可解析的文章条目。
- **有效但暂无条目**：订阅格式有效，但该次响应没有条目。此次 45 个 arXiv 学科频道均属于这一状态，不代表已经成功采集论文。
- **检测失败**：可能是错误地址、TLS 证书、网站反爬、DNS、超时或当前服务器网络限制；不自动宣称永久失效，也不关闭安全校验来获得“成功”。
- **待检测**：当前数据库没有该来源的检查结果。

检测状态记录在 MySQL `source_health` 表。记录含最近检测、最近成功时间、响应耗时、条目数、错误和最多 5 条预览。条目数为本轮最多读取的 50 条，不是网站历史总量。检查结果 5 分钟内复用，最多 4 个网络检查并发、单源 22 秒。状态仅代表当前服务器观测；恢复数据库或更换网络后应重新检查。

## 维护目录

```powershell
# 修改脚本中的来源条目后重新生成目录：
python scripts/build_source_catalog.py
python scripts/init_db.py

# 全量检查，分域名控制频率，不创建订阅或发送通知：
python scripts/check_sources.py
# 只检查前 20 个：
python scripts/check_sources.py --limit 20
# 按 JSON ID 列表检查，指定结果文件（--force 跳过五分钟健康缓存）：
python scripts/check_sources.py --ids-file .runtime/expanded-source-ids.json --output .runtime/expanded-source-check-result.json
```

原有来源在 `scripts/build_source_catalog.py`，本轮扩展在 `scripts/source_extensions.py`；生成器版本为 2。来源 ID 由 URL 稳定生成。名称、语言或分类调整不会丢失检测历史；更换 URL 会产生新 ID，需要重新检测。检查结果默认位于 `.runtime/source-check-result.json`，扩展候选结果在 `.runtime/expanded-source-check-result.json`，不会提交运行数据或文章内容到 Git。

### 自动巡检与失败退避

Python 启动后 45 秒开始自动巡检，每轮最多检查 4 个到期来源，轮次间隔 60 秒；同一轮同一域名只选一个来源。可用来源约 24 小时检查一次，有效空订阅约 6 小时一次；失败来源按 15、30、60 分钟等指数退避，基础上限 24 小时。每个来源额外错峰 0～10%，实际检查时间也可能因排队而延后。重启后依据数据库中的下次检查时间继续排期。

`SOURCE_HEALTH_ENABLED=false` 可关闭后台巡检，手动检查和订阅采集仍可使用。此调度面向单实例，不应在多个 Python 实例同时启动。

每次新检测累计总次数、成功次数、连续失败次数，并保存最近 20 次状态。有效空订阅计作传输/格式检查成功；历史成功率从本次升级后开始累计，旧记录不会推测补齐。最近文章时间来自 feed 提供的发布时间，缺失时显示未知。源内容质量分只评估本次 RSS 文本抽取，不代表媒体可信度或事实准确度。超过 48 小时未检测的记录会标为过期。

错误分为请求超时、地址不存在、访问受限、站点限流、HTTP 异常、TLS 证书、DNS、安全限制、格式异常和一般网络异常。连续失败不会擅自删除来源或改变用户订阅设置。

## 订阅试采与正文质量

在新建或编辑订阅弹窗中描述需求或配置兼容关键词，点击“试采预览”。无需先填写订阅名称或保存。试采最多读取前 5 个来源，展示各来源读取结果和失败原因；兼容模式关键词按标题/源摘要进行不区分大小写的任一匹配；语义模式跳过关键词过滤，由模型审核可读候选。

自动匹配模式只需填写主题，试采会合并系统与额外来源。试采只读取已有健康状态，不主动检查未验证的候选；新数据库可先等待界面匹配校验完成再试采。候选样本随目录、健康状态和来源内容更新而变化。

最多评估前 10 条匹配项，尝试补全其中 3 条正文，并展示候选内容、质量标记和拦截原因。正式采集会补全更多正文，并进一步去重和风险审核；试采样本不承诺全部最终发布。兼容试采阶段时限 40 秒，语义试采阶段时限 240 秒（需求理解在此前执行），同一用户最多一个正在运行的试采，10 秒内重复请求会限流，全局并发为 3。

试采不创建订阅、任务、文章、通知或投递记录，不更新来源健康统计；语义试采会调用模型，兼容模式不调用模型。源读取最多 12 秒，正文补全最多 8 秒；正式采集相应上限为 22 秒和 12 秒。正式正文补全最多 20 条、并发 3。

正文质量分与标记来自可解释规则：正文片段、摘要、过短内容、仅链接元数据、验证页、疑似导航页、空正文。验证页、疑似导航页和空正文会在入库前拦截，任务详情可查看原因；短摘要和链接元数据保留并明确标记。补全文本评分更高且可读时才替换来源正文，避免验证页覆盖有用摘要。旧文章显示“尚未评估”，不会猜测回填评分。

质量规则不能保证识别所有异常或证明全文完整，原文链接始终保留。完整原始响应归档、PDF 提取和专用站点解析器尚未加入本轮能力。

arXiv 学科 URL 遵循其[官方 RSS 说明](https://info.arxiv.org/help/rss.html)。HN RSS 等为第三方转换频道；这类地址的稳定性由对应服务决定。

接入依据：[GitHub Releases API](https://docs.github.com/en/rest/releases/releases#list-releases)、[JSON Feed 1.1](https://www.jsonfeed.org/version/1.1/)、[RSS Autodiscovery](https://www.rssboard.org/rss-autodiscovery)。本轮回归命令为 `python scripts/source_coverage_check.py`，使用普通临时账号访问真实公开源，不调用模型或机器人；结束会暂停本脚本的测试订阅。它需要先启动本地项目，验证结果在 `.runtime/source-coverage-result.json`。

## 边界

本目录主要由原站公开 RSS 和少量第三方转换频道组成。网页/JSON API 仍可在“我的订阅”手动配置。没有把需登录的微信公众号、知乎、抖音等平台伪装为已经接通，也没有默认依赖公开 RSSHub 代理。后续接入 RSSHub 应使用明确维护的实例，并逐条验证路由。

RSS 可能只提供摘要。PDF、付费正文、JavaScript 动态页面和需要登录的内容不保证可取得全文。来源目录不会自动订阅任何频道，也不会把测试内容混入真实资讯。
