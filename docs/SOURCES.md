# 数据源目录与维护

目录文件：`nexus-python/app/data/sources.json`。当前包含 217 个不同 URL 的 RSS/Atom 频道，来自 161 个域名。频道数包括同一网站的不同栏目和 arXiv 不同学科，不代表 217 家独立媒体。

分类包含人工智能、科技数码、编程与开源、网络安全、科学与学术、新闻资讯、商业财经、设计与产品、生活与文化。中文来源包括少数派、IT之家、Solidot、阮一峰、美团技术团队、博客园等；英文来源包括 GitHub Blog、OpenAI、Google、技术项目官方博客、学术和媒体频道。

## 使用

1. 进入工作台的“数据源中心”，按名称、主题、域名、分类、语言或状态筛选。
2. 点击“预览与检测”查看真实标题、摘要、最近检测时间及错误；检测会读取 RSS，不触发文章发布或推送。
3. 跨页最多选择 20 个来源，加入一个新订阅，或合并到现有订阅。合并时按 URL 去重，并保留已有订阅的关键词、暂停状态、AI 开关和采集间隔。
4. 新订阅默认每 60 分钟采集、AI 关闭；来源较多时应按主题拆成多个订阅。
5. “导出 OPML”导出当前筛选条件下的全部来源，可导入其他 RSS 阅读器。

## 可用性含义

2026-10-26 本机完整检查的结果：**119 个可返回文章、45 个有效但当前无条目、53 个失败**。完整目录都进行了请求和解析，不把未验证来源标成成功。

- **可用**：该次请求成功，返回可解析的文章条目。
- **有效但暂无条目**：订阅格式有效，但该次响应没有条目。此次 45 个 arXiv 学科频道均属于这一状态，不代表已经成功采集论文。
- **检测失败**：可能是错误地址、TLS 证书、网站反爬、DNS、超时或当前服务器网络限制；不自动宣称永久失效，也不关闭安全校验来获得“成功”。
- **待检测**：当前数据库没有该来源的检查结果。

检测状态记录在 MySQL `source_health` 表。记录含最近检测、最近成功时间、响应耗时、条目数、错误和最多 5 条预览。条目数为本轮最多读取的 50 条，不是网站历史总量。检查结果 5 分钟内复用，最多 4 个网络检查并发、单源 22 秒。状态仅代表当前服务器观测；恢复数据库或更换网络后应重新检查。

## 维护目录

```powershell
# 修改脚本中的来源条目后重新生成目录：
python scripts/build_source_catalog.py
python scripts/init_db.py

# 全量检查，分域名控制频率，不创建订阅或发送通知：
python scripts/check_sources.py
# 只检查前 20 个：
python scripts/check_sources.py --limit 20
```

来源 ID 由 URL 稳定生成。名称、语言或分类调整不会丢失检测历史；更换 URL 会产生新 ID，需要重新检测。检查结果文件位于 `.runtime/source-check-result.json`，不会提交运行数据或文章内容到 Git。

### 自动巡检与失败退避

Python 启动后 45 秒开始自动巡检，每轮最多检查 4 个到期来源，轮次间隔 60 秒；同一轮同一域名只选一个来源。可用来源约 24 小时检查一次，有效空订阅约 6 小时一次；失败来源按 15、30、60 分钟等指数退避，基础上限 24 小时。每个来源额外错峰 0～10%，实际检查时间也可能因排队而延后。重启后依据数据库中的下次检查时间继续排期。

`SOURCE_HEALTH_ENABLED=false` 可关闭后台巡检，手动检查和订阅采集仍可使用。此调度面向单实例，不应在多个 Python 实例同时启动。

每次新检测累计总次数、成功次数、连续失败次数，并保存最近 20 次状态。有效空订阅计作传输/格式检查成功；历史成功率从本次升级后开始累计，旧记录不会推测补齐。最近文章时间来自 feed 提供的发布时间，缺失时显示未知。源内容质量分只评估本次 RSS 文本抽取，不代表媒体可信度或事实准确度。超过 48 小时未检测的记录会标为过期。

错误分为请求超时、地址不存在、访问受限、站点限流、HTTP 异常、TLS 证书、DNS、安全限制、格式异常和一般网络异常。连续失败不会擅自删除来源或改变用户订阅设置。

## 订阅试采与正文质量

在新建或编辑订阅弹窗中填写来源及可选关键词，点击“试采预览”。无需先填写订阅名称或保存。试采最多读取前 5 个来源，展示各来源读取结果和失败原因；关键词按标题/源摘要进行不区分大小写的任一匹配，与正式 Scout 相同。

最多评估前 10 条匹配项，尝试补全其中 3 条正文，并展示候选内容、质量标记和拦截原因。正式采集会补全更多正文，并进一步去重和风险审核；试采样本不承诺全部最终发布。试采总时限 40 秒，同一用户最多一个正在运行的试采，10 秒内重复请求会限流，全局并发为 3。

试采不创建订阅、任务、文章、通知或投递记录，不调用 AI，不更新来源健康统计。源读取最多 12 秒，正文补全最多 8 秒；正式采集相应上限为 22 秒和 12 秒。正式正文补全最多 20 条、并发 3。

正文质量分与标记来自可解释规则：正文片段、摘要、过短内容、仅链接元数据、验证页、疑似导航页、空正文。验证页、疑似导航页和空正文会在入库前拦截，任务详情可查看原因；短摘要和链接元数据保留并明确标记。补全文本评分更高且可读时才替换来源正文，避免验证页覆盖有用摘要。旧文章显示“尚未评估”，不会猜测回填评分。

质量规则不能保证识别所有异常或证明全文完整，原文链接始终保留。完整原始响应归档、PDF 提取和专用站点解析器尚未加入本轮能力。

arXiv 学科 URL 遵循其[官方 RSS 说明](https://info.arxiv.org/help/rss.html)。HN RSS 等为第三方转换频道；这类地址的稳定性由对应服务决定。

## 边界

本目录主要由原站公开 RSS 和少量第三方转换频道组成。网页/JSON API 仍可在“我的订阅”手动配置。没有把需登录的微信公众号、知乎、抖音等平台伪装为已经接通，也没有默认依赖公开 RSSHub 代理。后续接入 RSSHub 应使用明确维护的实例，并逐条验证路由。

RSS 可能只提供摘要。PDF、付费正文、JavaScript 动态页面和需要登录的内容不保证可取得全文。来源目录不会自动订阅任何频道，也不会把测试内容混入真实资讯。
