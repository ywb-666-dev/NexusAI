# 个性化内容推荐

内容中心默认“为你推荐”，只对当前用户已发布、非重复、明确通过 LLM 语义筛选的文章进行排序。“最新内容”“推荐优先”继续提供原有阅读方式；未经过语义筛选的旧文章不自动进入个性化推荐。

在阅读抽屉中选择喜欢、收藏、不感兴趣，支持分别撤销。收藏可通过“仅看收藏”筛选；被标记不感兴趣的文章保留在最新内容中，方便撤销。负反馈优先于同时存在的喜欢或收藏。没有点击不代表不喜欢，不记录阅读时长或推断用户尚未表达的行为。

## 当前算法

第一版为基于内容的混合排序，不额外调用模型，也不使用其他用户数据：

1. 从筛选范围内最近采集的最多 500 篇语义推荐中召回候选。页面总数是本次池内排序、排除和精确 URL 去重后的数量，不是全库总量。
2. 标题前 300 字符和摘要前 600 字符提取英文词与中文双字词，用 TF-IDF 构建归一化向量。它不具备跨语言向量模型的语义理解能力；前置语义判断仍由原有模型负责。
3. 最近 200 篇有有效显式反馈的已发布文章构成当前用户兴趣画像。喜欢权重 +2、收藏 +3、不感兴趣 -3；反馈按 90 天半衰期衰减。取消全部反馈后该条不再参与画像。即使负反馈超出画像预算，被标记的文章本身仍从推荐与新简报中排除。
4. 基础分 = 0.50 × 订阅语义相关度 + 0.15 × 正文质量 + 0.15 × 时效 + 0.20 × 兴趣匹配。无反馈时兴趣分为中性的 50。兴趣使用画像与文章向量的余弦相似度映射到 0～100；时效以发布时间为准，缺失时用采集时间，半衰期 7 天；未来时间按零年龄计算。
5. 用 MMR 风格的贪心重排，减去与已选内容的最大文本相似度 ×12，以及同域名与同订阅的轻量惩罚（分别每次 4/2 分，各最多累计两次）。精确 URL（忽略片段）仅保留一次；这是多样性排序，不是全库语义事件聚类。

算法版本为 `content-tfidf-v1`，分值是人工设定权重的排序分，不是点击率或事实准确率。没有协同过滤、训练好的排序模型或线上 A/B 结论。当前反馈是动态兴趣画像的输入，不会训练底层大语言模型。

推荐响应提供分数组成、推荐理由、冷启动标识和版本。新用户使用订阅相关度、质量、时效排序。个性化分值不能将未通过语义审核或待审批内容变成可推荐内容。

## 简报与数据

新生成的个人情报简报在时间范围内最多召回 500 篇候选，复用同一画像与排序，再选择最多 40 篇进入原有精确去重和模型汇总。负反馈排除应用于所有反馈记录，不局限最近 200 条。历史简报保留原快照，不因后续反馈重写。简报生成仍会调用已配置模型，排序本身不增加模型调用。

新增 `content_feedback` 表，复合主键为 user_id/content_id。喜欢、收藏、不感兴趣是独立状态；更新只修改提交的字段。接口检查登录、文章归属和已发布状态，并使用数据库 upsert 保证重复反馈不会重复累计权重。用户之间不共享画像。

- `GET /api/python/contents?sort=personalized`：个性化排序，返回 recommendation、feedback 与覆盖信息。
- `GET /api/python/contents?sort=latest&saved=true`：查询收藏，包括可撤销的负反馈内容。
- `PUT /api/python/contents/{id}/feedback`：例如 `{"liked":true}`、`{"saved":false}`、`{"dismissed":true}`；必须为真正的布尔值。

## 验证

`python -m pytest nexus-python/tests -q` 覆盖冷启动、正负反馈、撤销、时效、准入、多样性、中文/英文特征和原有回归。

启动项目后运行 `python scripts/recommendation_check.py`：隔离普通账号验证真实数据库反馈与排序变化、用户隔离、收藏过滤、简报选材排除及浏览器交互。资料和语义评分为明确预置的合成验收样本，简报模型调用使用替身，只检验选材；不调用真实模型、不发送机器人消息，不代表总体推荐准确率。

结果保存在 `.runtime/recommendation-result.json`，桌面/手机截图同目录。当前没有足够真实反馈数据来报告 Precision@K、NDCG 或点击率提升。池大小、画像预算、文本特征局限和固定权重是当前版本的明确边界。
