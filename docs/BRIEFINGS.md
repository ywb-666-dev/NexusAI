# 个人情报简报

在工作台“个人情报简报”选择近 24 小时或近 7 天，点击生成。任务异步执行，离开页面后仍可在历史中阅读；生成失败会如实显示，可手动重新生成。生成会调用已配置的模型，无模型或无效模型结果不会伪造成成功的智能简报。

## 内容范围与依据

- 只汇总当前用户订阅下已发布、非重复、明确通过语义筛选的内容。待审批、被拒绝和关键词模式文章不纳入。
- 时间范围按 **采集时间**，不是文章发布时间。某篇旧文章刚被采集时可能进入本期，模型被要求不把它描述成刚发生。
- 每期最多选取 40 篇：先按 UTC 采集日从新到旧，再按当日相关度与采集时间排序。页面明确显示预算之外的数量。
- 先去除精确重复网址（忽略片段及常见跟踪参数）或相同正文，再由模型合并同一事件的多源报道。仅合并事件，不声称完成全库语义去重。
- 模型最多整理 12 个重点，说明事实摘要与关注建议；未列入重点的候选需说明原因。保留来源分歧，不能擅自消除矛盾。
- 每篇候选只能出现在一个事件或一条遗漏说明中。后端检查资料 ID 的完整覆盖、归属和逐字引文，禁止未知 ID、重复引用、空白或编造引文。原文链接由服务器提供，模型不能生成链接。
- 每篇模型资料上限：标题 300 字符、摘要 600 字符、正文片段 1200 字符、订阅需求 1000 字符及推荐理由 400 字符。无法涵盖文章全文；引用检查不代表摘要事实经过独立验证，也不能完全消除模型误判或指令干扰。

页面可以展开原文、引文、原订阅和推荐理由，导出 Markdown。历史简报保存当时的资料快照与模型标识，不随订阅条件修改而重写。

## 自动整理与推送

自动整理、自动推送默认关闭，可分别控制。开启自动整理后，从下一个北京时间 **08:00** 起生成近 24 小时简报，服务按分钟轮询；当天因服务停机错过时，会在恢复后补生成当天一份，不追补过去多天。不是严格准点的外部定时服务。

自动生成每天每用户使用唯一日期键，手动生成按用户限制一个进行中任务。自动推送需要同时开启自动整理与“同时推送到已启用的机器人”，并已配置可用飞书或钉钉渠道。手动生成不会因自动推送开关开启而直接发送，需要在简报中点击“推送简报”。无内容时不调用模型，也不向机器人发送空简报。

简报复用推送设置中的渠道、签名、有限重试和投递记录。相同简报和渠道使用唯一投递键，重复点击会跳过已有记录；失败可在推送设置中重试。生成成功和推送成功分别记录，不把推送失败显示成生成失败。机器人消息受既有约 15KB 长度上限约束，长简报请在站内阅读或导出。

服务重启会将中断的生成标记失败并释放占位。未确认的简报投递标记失败，需要先检查群消息再决定重试；网络中断后的远端接收结果可能不明确，不能保证外部平台端严格只收到一次。

当前调度与启动恢复适用于项目现有单 Python 服务实例。没有跨实例租约和独立任务队列，部署多个实例前需升级任务协调。

## 接口与存储

所有接口均要求 JWT；读写和推送按用户隔离。

- `GET /api/python/briefings?page=1&size=12`：分页历史。
- `POST /api/python/briefings`：`{"hours":24}` 或 `{"hours":168}`，返回任务 ID。
- `GET /api/python/briefings/{id}`：状态、时间范围及完整简报。
- `GET/PUT /api/python/briefings/preferences`：`{"enabled":false,"pushEnabled":false}`。
- `POST /api/python/briefings/{id}/push`：手动向当前用户启用的渠道提交投递。

新增 `briefing`、`briefing_preference` 表，启动脚本会通过现有非破坏初始化创建，不清空现有数据。`briefing` 保存 queued/generating/ready/failed、资料快照、报告与去重/预算数量；投递记录通过 `briefing:` 前缀关联简报，失败重试入口支持该类型。

生成并发最多 2，单次执行上限 240 秒，模型调用外层 150 秒并复用结构化模型请求的读取超时。没有另加收费套餐或日配额，重复手动生成仍会消耗模型用量。

## 验证方式

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'
python -m pytest nexus-python/tests -q

# 会调用当前真实模型处理少量明确标注的虚构验收资料；
# 新建隔离的普通测试账号，不向真实机器人发送消息。
python scripts/briefing_check.py --real-model
```

结果在 `.runtime/briefing-result.json`，截图在 `.runtime/briefing-desktop.png`、`.runtime/briefing-mobile.png`。真实模型验证事件合并和引用；机器人幂等投递、失败重试和坏模型输出使用明确的进程内替身验证，不将其作为真实平台送达证明。

本轮真实模型将 3 篇有效的合成资料整理为 2 个事件，合并同一项目的两份报道并保留性能数据差异。联调同时覆盖每日唯一生成、自动投递开关、恢复逻辑、空状态及用户隔离；这组小样本不代表对所有真实报道的汇总准确率。
